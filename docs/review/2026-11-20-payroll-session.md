# 급여 요율·로그인 키 (`fix/payroll-session-hardening`)

- 날짜: 2026-11-20
- 리뷰어: Cursor
- 범위: `862a4b1..9cc9616`. 급여 JSON 요율, 고시 밖 달, `SESSION_SECRET`, DB 포트, `_to_delete` 추적 해제, `geo-map` 타입
- 기준: `dev`(`862a4b1`)와 비교. 작업 트리는 커밋 시점 기준

## 결론

계산은 JSON 정수 분수다. 고시 밖이면 금액을 만들지 않고, 저장·전표·추이도 그 달을 쓴다. 고시 밖 달의 급여 행은 0원으로 넣지 않고 지운다.

## 개선 제안

- 저장은 미리보기와 같은 `payMonth`를 쓰고, `status !== "ok"`이면 그 달의 급여·세금 행을 쓰지 않는다.
- 임금명세서도 `status === "unavailable"`이면 공제 칸을 비운다.

## 잘된 점

- 4.75%·7.19%·장기요양·고용보험이 `payroll-rates-2026.json` 정수 분수다. 300만 원 기존 값(연금 142,500 · 건보 107,850 · 장기요양 14,172 · 고용 27,000)과 가짜 요율 0.1 테스트가 있다.
- 고시 밖 `2025-06`·`2027-07`은 `unavailable`과 `null`이다. 상·하한을 지어내지 않는다.
- 본인 기본공제 1,500,000은 그대로이고 출처만 소득세법 제50조, `verifiedBy`는 미검증이다. 사용자가 2026-11-12에 확인한 다른 요율은 유지됐다.
- 쿠키 서명은 `SESSION_SECRET`. 비밀번호는 비교에만 쓴다. 실패 대기는 횟수 × 500ms, 최대 5초. 테스트가 있다.
- `_to_delete`는 추적만 해제했다. 디스크 파일은 남았다.
- `pnpm typecheck` 8패키지 통과. core 테스트 81파일 365개 통과. `docs/review/2026-11-19-claude.md`는 없다.
