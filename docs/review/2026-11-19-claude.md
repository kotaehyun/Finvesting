## 2. 재무제표 파이프라인 (11-06 지적, 미반영)

### 🔴 #1 보유 코스닥 종목의 market이 KRX로 덮어씌워짐
- 위치: `apps/worker/src/sources/dart.ts:43,63`, `company-profile.ts:165,184`, `apps/worker/src/lib/instruments.ts:17-22`
- 내용
  - `held = [...보유·관심, ...섹터 목록]`을 `new Map`으로 만든다. 섹터 목록은 전부 `market: "KRX"`이고, Map은 뒤의 값이 앞을 덮는다.
  - 그래서 리노공업·이오테크닉스처럼 코스닥 종목을 보유 중이어도 `KRX`로 넘어간다.
  - `ensureInstrument`는 같은 6자리 종목을 찾으면 **기존 행의 market·name·currency를 UPDATE**한다.
  - 결과: 매주 월요일 03:00 수집 때마다 사용자의 종목 데이터가 바뀐다.
- 수정: Map에서 보유 종목이 이기게(`if (!map.has(k))`). 수집기는 이미 있는 종목의 market을 바꾸지 않게.

### 🔴 #2 DART 반기·3분기 손익이 3개월치일 가능성
- 위치: `apps/worker/src/sources/dart.ts:108`
- 내용
  - 분기 보고서 손익은 `thstrm_amount`(그 3개월)와 `thstrm_add_amount`(연초부터 누적)가 따로 온다. 코드는 앞의 것만 읽는다.
  - 현금흐름(`fnlttSinglAcntAll`)은 원래 누적이다. 같은 `H1` 행 안에서 손익은 3개월, 현금흐름은 6개월이 섞인다.
- 수정: 실제 응답 하나(삼성전자 2025 반기 `11012`)의 `thstrm_dt`·두 금액을 찍어 확인. 맞으면 H1·Q3의 IS/CIS만 `thstrm_add_amount` 우선.

### 🔴 #3 EDGAR 10-Q에서 3개월치와 YTD가 무작위로 섞임
- 위치: `apps/worker/src/sources/edgar.ts:70-75`
- 내용
  - companyfacts의 `fy`/`fp`는 공시 단위다. 10-Q 2분기 하나에 같은 `end`로 3개월 값과 YTD 값이 같이 있다.
  - `end`로만 정렬해 첫 값을 쓰므로 어느 쪽이 저장될지는 배열 순서에 달렸다.
- 수정: `Fact`에 `start` 추가, 기간 길이로 고른다(income·cashflow는 YTD, balance는 그대로). 부문매출 파서(`edgar-xbrl-segments.ts`)는 이미 `startDate`를 본다.

### 🟠 #4 `/statements`가 올해 부분 실적을 기간 표시 없이 보여줌
- 위치: `packages/api/src/lib/statements.ts:98,133-135`, `packages/core/src/statement-collect.ts:37`
- 내용
  - 기본 연도가 `years[0]` = 2026. 사업보고서가 없어 분기 자료만 있다.
  - 우선순위가 `FY → H1 → Q3`라 3분기가 있어도 반기가 먼저 뽑힌다.
  - 손익·재무상태·현금흐름을 각각 고르므로 한 화면에 다른 기간이 섞일 수 있다.
  - 응답·화면에 `fiscalPeriod`가 없다. ROE 같은 비율도 부분 기간 손익 ÷ 시점 잔액이 된다.
- 수정: 기본은 FY가 있는 최신 연도. 우선순위 `FY → Q3 → H1 → Q1`. 세 표 기간을 맞춤. 응답에 `fiscalPeriod`, 화면에 "2026 · 3분기 누적". FY가 아니면 연간 비율 숨김.

- 내용: `statement-targets.ts`는 AMEX를 수집하는데 화면 칸 목록에는 없다.

### 🟡 #6 기업정보 요청 일부가 재시도 없이 `fetch`

## 3. 이번 변경 리뷰 (`ff2f858`, `dfc1368`)

### 🟠 #7 급여 공제: 검증한 JSON이 계산에 쓰이지 않음
- 위치: `packages/core/src/payroll.ts:130-135`
- 내용
  - `payroll-rates-2026.json`을 원문과 대조해 `verifiedBy: 사용자`로 바꿨다. 그런데 계산은 숫자를 코드에 박아 둔다: `475/10_000`(국민연금), `719/20_000`(건강보험), `9_448/71_900`(장기요양), `9/1_000`(고용보험).
  - 지금은 값이 같아 결과가 맞다. 내년에 JSON만 고치면 화면 숫자는 그대로다.
  - 130행: 고시 기간 밖의 달(2027-07 이후, 2025년)은 국민연금 상·하한 없이 세전 전액으로 계산한다. 고소득자는 실제보다 크게 나온다. 프로젝트 규칙(실패는 빈 칸+status)과 맞지 않는다.
  - `basicPersonalExemption`(150만)의 출처가 4대보험 연계센터 홈페이지로 적혀 있다. 기본공제는 소득세법 제50조 항목이다.
- 수정: JSON 값을 정수 분수로 바꿔 사용(부동소수 회피 목적 유지). "JSON을 바꾸면 결과가 바뀐다" 테스트. 기간 밖은 `null`/`unavailable`.

### 🟠 #8 로그인: 비밀번호를 서명 키로 그대로 씀
- 위치: `packages/core/src/session.ts`, `apps/web/src/app/api/auth/login/route.ts`, `packages/api/src/trpc.ts`
- 좋은 점: tRPC 컨텍스트에서 막는다. 쿠키 httpOnly·SameSite=lax. 상수 시간 비교. 검증 기록에 401 확인까지 있음(`2026-11-11-cursor-local-session.md`).
- 내용
  - `APP_PASSWORD`가 곧 HMAC 키다. 쿠키 하나가 유출되면 서명 대상(`userId.exp`)이 공개돼 있어 오프라인 무차별 대입으로 비밀번호를 맞춰 볼 수 있다.
  - 로그인 시도 횟수 제한이 없다. 외부에 열면 온라인 대입이 된다.
  - 참고: `secure`가 `NODE_ENV=production`일 때만 붙는다. 운영 모드로 `http://192.168.x.x`에서 띄우면 브라우저가 Secure 쿠키를 받지 않아 로그인 반복.
- 수정: `SESSION_SECRET`(무작위 32바이트+)으로 서명, 비밀번호는 비교에만. 실패마다 지연 증가.

### 🟠 #9 네이버 뉴스 API: 요금 근거 없이 켬
- 위치: ADR 0057, `apps/worker/src/sources/naver-news.ts`
- 내용
  - ADR 0051은 "종량제라 안 쓴다"였다. 0057로 뒤집으면서 "단가 표는 확인하지 않았다"고 적었다.
  - 확인 결과(NCP 가이드 「NAVER API HUB 사용 준비」): 종량 요금제지만 **현재 한시적 무료**, 유료 전환 시 사전 공지. 콘솔 Application에 **이용 한도 설정·임계치 알림**이 있다.
  - 지금 수집량은 하루 최대 160회(40검색 × 4회).
- 수정: 콘솔에서 한도(예: 하루 300회)와 알림 설정. ADR 0057에 "한시 무료(확인일), 한도 N회 설정" 추가.

### 🟡 #10 챗: 실패·중단된 답의 저장

- 수정: 실패 시 사용자 메시지 롤백, 또는 `status`(complete/aborted) 칸. 세션 소유권 확인은 모든 조회에 있음(좋음).
