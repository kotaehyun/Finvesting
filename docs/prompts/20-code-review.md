# 코드 리뷰 프롬프트

---

## 작업: 코드 리뷰 — {대상: 파일/패키지/커밋 범위}

### 리뷰 관점 (순서대로)
1. **정확성**: 금액 계산(부호, 수수료·세금 반영, 환율), 날짜/시간대(KST vs UTC), 멱등성(중복 저장)
2. **규칙 위반**: 패키지 의존 규칙, core 순수성, web/mobile의 DB 직접 접근, npm/yarn 사용
3. **데이터 안전**: 금융 데이터 외부 전송 여부, 키·비밀값 하드코딩, 뉴스 본문 저장
4. **오류 처리**: 수집기 실패 시 다른 소스 영향, API 입력 검증(zod)
5. **성능**: N+1 쿼리, 인덱스 없는 조회, 불필요한 전체 조회
6. **가독성·문서 일치**: 코드와 `docs/tech/*`가 어긋난 곳

### 출력
`docs/review/YYYY-MM-DD-{대상}.md`를 review/README.md 형식으로 작성한다. 문제마다 심각도(높음/중간/낮음), 위치(파일:줄), 내용, 수정 제안을 쓴다. 바로 고칠 수 있는 낮음 항목은 고치되, 높음/중간은 **먼저 보고하고 확인 후** 수정한다. 목록 표에 한 줄 추가한다.
