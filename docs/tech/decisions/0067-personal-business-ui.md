# 0067 — 일반 계정과 비즈니스 계정은 화면을 따로 둔다

- 상태: 채택 (2026-11-23, 사용자 「작업을 진행하자」로 확정). 1단계 구현 `feat/account-mode-shell`
- 배경
  - 2026-11-23 UI/UX 점검(`docs/review/2026-11-23-uiux-claude.md`)에서 한 앱 안에 화면 계열이 다섯 개였다. 카드형·밝은 ERP·어두운 ERP·대시보드형·챗.
  - 개인 사용자에게는 ERP 표·전표·남색 도구 띠가 어렵고, 사업자에게는 카드형 요약이 일하기 불편하다. 한 화면으로 둘을 다 맞추려다 섞였다.
  - 사용자 방향(2026-11-23): **비즈니스 계정 UI/UX와 일반 계정 UI/UX를 다르게 한다.**

## 결정

### 1. 계정 모드 두 개
| 모드 | 대상 | 화면 계열 | 말투 |
|---|---|---|---|
| **일반** (`personal`) | 근로자·개인 투자자 | 카드형 하나 | 쉬운 말 (「내야 할 세금」, 「돌려받을 돈」) |
| **비즈니스** (`business`) | 프리랜서·개인사업자·법인 | ERP형 하나 (지금 wehago 뼈대) | 업무 용어 (「원천세」, 「매입·매출」, 「전표」) |

- 모드는 **화면만** 바꾼다. 데이터(원장·계좌·체결·세금 자료)는 같다. 모드를 바꿔도 지워지거나 숨겨지는 데이터는 없다.
- 저장: 쿠키 `finvesting_ui_mode` (`personal` | `business`, 없거나 모르는 값이면 `personal`). 1년 유지.
  - 처음 초안은 `users.ui_mode`(DB)였다. 1단계에서 쿠키로 바꿨다. 모드는 화면 설정이라 기기마다 달라도 되고(맥=비즈니스, 윈도우=일반), 웹은 DB에 직접 붙지 않으며(규칙 6), 서버 레이아웃이 첫 화면부터 맞는 셸을 그리려면 요청에 값이 있어야 한다.
  - 여러 사용자(4단계)가 되면 계정 설정으로 옮길지 다시 정한다.
- 전환: 머리말 오른쪽 스위치 「일반 / 비즈니스」. 바꾸면 그 모드의 홈으로 간다.
- 근로소득만 있는 사용자는 일반, `WorkRole`이 `freelancer|business|corporation`이면 처음 켤 때 비즈니스를 권한다(강제하지 않음). — 1단계에는 없음. 3단계에서.

### 2. 메뉴
**일반** (위쪽 한 줄, 6개)
| 메뉴 | 들어가는 화면 |
|---|---|
| 홈 | 순자산·이번 달·확인할 일 |
| 돈의 흐름 | 타임라인, 계좌·거래 |
| 투자 | 보유, 투자 대시보드, 시장, 기업(재무제표·펀더멘털 요약), 뉴스·오피니언 |
| 집 | 부동산 |
| 세금 | 연말정산 미리보기, 배당·이자, 해외주식 양도세 (쉬운 말) |
| AI 비서 | 챗 |

**비즈니스** (왼쪽 트리 메뉴, ERP)
| 묶음 | 들어가는 화면 |
|---|---|
| 대시보드 | 이번 달 매출·비용·현금, 확인할 일 |
| 장부 | 계좌·거래, 회계전표, 내보내기(더존·위하고·세무사랑) |
| 세무 | 원천세·종소세·부가세 자료, 연말정산, 양도세 |
| 급여·인사 | 근로자 대장(프로필대장), 급여 명세 |
| 투자·기업 | 보유, 재무제표, 펀더멘털 |
| 시장 | 투자 대시보드, 시장, 부동산, 뉴스 |
| AI | 챗 |

### 3. 공통으로 남기는 것 (두 모드 모두)
- 색 규칙: 가격·손익은 빨강 오름 / 파랑 내림, 0은 중립(`--tone-up/down/flat`). 돈의 방향은 부호로. → `docs/tech/ui.md`, UI 리뷰 U1~U4.
- 다크·라이트 둘 다 지원. ERP도 다크를 따른다.
- 숫자 포맷 함수, 기준일 배지, 로딩·빈 화면·오류 컴포넌트.
- 종목 이름: 국내는 DART 한국어 회사명 우선.

### 4. 하지 않는 것
- **ADR 0050은 그대로다.** 비즈니스 모드는 지금 있는 화면(세금·회계전표·재무제표·펀더멘털·프로필대장·`/erp` 보기)을 ERP 뼈대로 다시 배치하는 것까지다. 급여 계산·4대보험 신고·부가세 계산 같은 **새 업무 기능은 0050 재개 지시 전에 만들지 않는다.** 비즈니스 메뉴에서 아직 없는 칸은 「준비 중(ADR 0050)」으로 보인다.
- 모드별로 데이터를 나누지 않는다. 여러 사용자·권한(ADR 0056 4단계)과는 별개다.
- 같은 기능을 모드마다 두 번 만들지 않는다. 계산·조회는 core·api 하나, 모드는 **보여 주는 컴포넌트만** 다르다.

## 구현 구조
```
packages/core/src/ui-mode.ts  # 모드·쿠키 이름·메뉴 두 벌·현재 위치 판정 (테스트 ui-mode.test.ts)
apps/web/src/app/
  layout.tsx                 # 쿠키 읽어 AppShell에 모드 전달
  app-shell.tsx              # PersonalShell(위 6개+둘째 줄) / BusinessShell(왼쪽 트리) / 모드 스위치
  shell.css                  # 셸 스타일 (globals.css 분리의 첫 조각)
  _shared/                   # (3단계) 머리말, 기준일 배지, 포맷, 로딩/빈/오류
apps/web/src/styles/
  tokens.css  card.css  erp.css  chat.css   # globals.css 분리
```
- 같은 URL을 두 모드가 다르게 그릴 때(예: `/tax`)는 페이지가 `mode`를 보고 `PersonalTax` / `BusinessTax` 컴포넌트를 고른다. 데이터 훅은 하나.

## 결과
- 개인 사용자는 카드형 6메뉴만 본다. ERP 표·전표 용어가 나오지 않는다.
- 사업자는 ERP 한 계열만 본다. 메뉴를 옮겨도 화면 모양이 바뀌지 않는다.
- 지금 세금·회계·펀더멘털에 들어간 「쉬운 말」 작업(11-22)은 일반 모드 쪽으로, wehago 뼈대는 비즈니스 모드 쪽으로 간다.

## 단계
1. 모드 쿠키 + 스위치 + 레이아웃 셸 두 개 + 메뉴 두 벌 (화면 내용은 그대로) — **완료 2026-11-23**
2. 공통 토큰·다크 모드·색 규칙(UI 리뷰 U1~U4) — `feat/ui-unify-tones`
3. 일반 모드 화면을 카드형으로 맞춤: 세금(쉬운 말), 보유·계좌
4. 비즈니스 모드 화면을 ERP로 맞춤: 홈→대시보드, 타임라인→장부 보기. ERP 화면 자체의 왼쪽 메뉴(`.erp-menu`)와 셸 트리 메뉴가 나란히 보이는 것을 여기서 하나로 합친다
5. `globals.css` 분리
